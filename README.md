# CrossingKey Design Language

**Public design and interaction reference for CrossingKey Intelligence.**

This repository defines the visual, interaction, and communication rules used to keep CrossingKey surfaces recognizable, disciplined, accessible, and commercially coherent. It is a public reference, not a dump of private brand assets or unreleased product work.

## Design thesis

CrossingKey uses a **future-antiquity** visual language: historical weight, engineered restraint, and modern machine precision. The system favors hierarchy, legibility, and deliberate signal over decorative noise.

### Nocturnum foundation

| Token | Value | Purpose |
| --- | --- | --- |
| Void Black | `#050508` | Primary ground and visual depth |
| Deep Panel | `#0b0b12` | Layered surfaces and containment |
| Soft Silver | `#d7d7df` | Information, contrast, structure |
| Atomic Hot Magenta | `#ff2bd6` | Scarce emphasis, action, state |

Atomic Hot Magenta is a signal color, not a default fill. Interfaces must remain understandable without color alone.

## Interaction standard

1. Establish hierarchy with type, spacing, proportion, and contrast before decoration.
2. Make system state and user authority visible.
3. Keep primary actions obvious and destructive actions deliberate.
4. Respect keyboard navigation, readable contrast, reduced motion, and semantic structure.
5. Use motion to explain change, never to conceal latency or decorate uncertainty.
6. State scope, price, delivery, status, and support boundaries in plain language.
7. Prefer authored composition over generic dashboard templates.

## Brand behavior

CrossingKey should feel technically serious without becoming sterile, distinctive without becoming noisy, and premium without relying on empty luxury language. Public surfaces should demonstrate quality through evidence, precision, and restraint rather than adjectives.
